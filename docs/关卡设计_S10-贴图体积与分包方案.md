## 一、决定性实测：图集打包到底省多少

用现有 29 张贴图做**六方案对照**（同一批图，只换打包/量化/分辨率）：

| 方案 | 29 张合计 | 折算单张 | 相对现状 |
|---|---|---|---|
| A 现状 · 192px 单张 PNG | 875 KB | 30.2 KB | — |
| **B 图集打包 · 192px** | **644 KB** | **22.2 KB** | **−26.4%** |
| C 图集 + 256 色量化 · 192px | 369 KB | 12.7 KB | −57.9% |
| E 图集打包 · 96px | 251 KB | 8.7 KB | −71% |
| F 图集 + 量化 · 96px | 132 KB | 4.6 KB | −84.8% |

**图集打包有效，但只有 −26%** —— 原因是：

> 牌面是**不透明整张方牌**（`192×192 RGB`，纸底铺满无 alpha）。
> 图集的三大收益里，**「裁掉透明边」这一项完全不适用**（没边可裁），
> 只剩「减少文件数 + DEFLATE 跨行冗余」两项 → 收益天然有限。

★ 这条要记下来：**图集打包的收益取决于贴图有没有 alpha 边**。本项目牌面是满幅方牌，别指望图集能省一半。

## 二、★ 硬约束：全库 299 张贴图，图集后仍超主包

### 2.1 全库到底要多少张

`Board.buildDeck()` 每对发 **1 张偏旁 + 1 张部件**；合成动画 `GamePage:1419` 另外取**整字**牌面。
所以三类都要烘：

| 类别 | 数量 | 说明 |
|---|---|---|
| 整字 | 103 → **145** | 目标条 + 合成成功动画 |
| 偏旁 | 21 → **29** | 新增 弓 氵 雨 日 禾 土 户 宀 |
| 部件 | 95 → **125** | 新增 ~30 个（玄瓜包青廷胡单也奚皮路林务军爰召凡舀惠央干云欠匀羽非册至吕兵失艮令） |
| **合计** | | **约 299 张** |

### 2.2 外推体积 vs 真实包体预算

构建产物体积构成（`build/wechatgame`，实测）：

```
cocos-js（引擎）  1380 KB
assets（资源）    2056 KB   ← 其中贴图仅 875 KB（只有 L1–L3 的 29 张）
其他                232 KB
------------------------------------
当前微信包         3.12 MB   （preview-info.json: 3270727 B）
```

**非贴图的固定占用 = 3.12 − 0.85 = 2.27 MB**（引擎 1.38 + 代码/音频/UI/场景 0.89）。
→ **主包留给贴图的预算 = 4 − 2.27 = 1.73 MB**。

| 贴图方案 | 全库 299 张 | 主包总包 | 结论 |
|---|---|---|---|
| 现状口径 · 192 单张 | 8.82 MB | 11.1 MB | ❌ 超主包 6.4× |
| **图集打包 · 192** | **6.48 MB** | **8.75 MB** | ❌ **超主包 2.2×** |
| 图集 + 量化 · 192 | 3.71 MB | 5.98 MB | ❌ 仍超主包 |
| 图集打包 · 96 | 2.54 MB | 4.81 MB | ❌ 仍超 |
| 图集 + 量化 · 96 | 1.35 MB | 3.62 MB | ✅ 唯一能进主包 |

> **结论：192px 的图集打包（6.48 MB）单独挡不住 4 MB 主包上限 —— 必须搭配「分包」。**

## 三、微信包体口径（已查证官方文档，2026-08）

| 项 | 上限 |
|---|---|
| **主包** | **≤ 4 MB** |
| 主包 + 全部分包合计 | ≤ 30 MB |
| **单个分包** | **不限制大小** |

微信官方明确推荐「**合理分包、按需加载**」，并配 `wx.preloadSubpackage` 支持后台预下载。
→ 对一个 4 章 38 关的游戏，**按章分包**是天然划法。

## 四、三条可行路线

### 路线 A · 192px 图集打包 + 按章分包（推荐）

| 包 | 内容 | 体积 |
|---|---|---|
| 主包 | 引擎 + 代码 + UI + 音频 + **第 1 章贴图 + 跨章公共偏旁/部件** | ≈ 3.5 MB ✅ |
| 分包 2 | 第 2 章新增贴图 | ≈ 0.8 MB |
| 分包 3 | 第 3 章新增贴图 | ≈ 1.6 MB |
| 分包 4 | 第 4 章新增贴图 | ≈ 1.0 MB |
| 合计 | | ≈ 6.9 MB ≤ 30 MB ✅ |

- ✅ **画质最好**（192px 全量保留，6×6 的 168 物理px 格宽仍 1.14× 过采）
- ✅ 分包用 `wx.preloadSubpackage` 在第 1 章游戏过程中**后台预拉**，玩家基本无感
- ⚠️ 需要：`make-tile-atlas.py` 按章分目录 + Cocos 配 Bundle（或 `game.json` 写分包）+ 首次进章时的加载态

### 路线 B · 192px 图集 + 256 色量化 + 单分包

| 包 | 内容 | 体积 |
|---|---|---|
| 主包 | 引擎 + 代码 + UI + 音频 | ≈ 2.3 MB ✅ |
| 分包 1 | **全部**贴图（3.71 MB） | 3.71 MB（不限大小 ✅） |
| 合计 | | ≈ 6.0 MB ✅ |

- ✅ 只需**一个**分包，构建配置最简单
- ⚠️ 量化（PNG-8）对水墨渐变的色阶有影响 —— **必须出对照图实测**才敢定（纸底有细噪点，压到 256 色可能出块状带纹）
- ⚠️ 全部贴图在一个分包 = 进第 1 关就得下完（无法按章渐进）

### 路线 C · 96px 图集 + 量化（不进分包）

| 包 | 内容 | 体积 |
|---|---|---|
| 主包 | 全部（含贴图 1.35 MB） | ≈ 3.62 MB ✅ 无需分包 |

- ✅ 工程最简单（改一个常量 `CELL 96→48`，重烘即可）
- ❌ **画质代价集中在小盘**：6×6 时格宽 58 设计px = **168 物理px**，
  96px 贴图 = **0.57× 严重欠采样**（糊）—— 而前 2 关正是新手第一印象
- ❌ 12×12（75 物理px）反而够用 → 等于"**越简单的关卡越糊**"，方向是反的
