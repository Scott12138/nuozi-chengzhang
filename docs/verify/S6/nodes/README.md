## 三、三态节点：拍板 → 实现对应关系

| 状态 | 用户要求 | 实现 |
|---|---|---|
| 已通关 | 奖杯**代替外面的圆圈** + 三星 | `MapPage.buildTrophyNode`：**无底圈**；奖杯宽 56 设计px，上方 11px 星槽 |
| 即将攻打 | 数字 **+** 简易山峦 | `MapPage.buildMountNode`：山宽 72；关号 19px 压在山脚，**必须加白描边**（山体亮度 ≈84，纯墨色对比不足） |
| 更后面未通关 | 锁 | `MapPage.buildLockedNode`：**沿用上一轮**，一行未改 |

⚠️ **已通关节点不再显示关号**。方案图里 ①②③ 是三个**互斥**的内容备选
（纯图标 / 关号 / 星级），用户选 ③ ⇒ 保留下来的是**星级**。
信息上不亏：地图是按顺序数着往下走的，"第几关"从位置可读；
"拿了几颗星"才是这一格唯一无法从位置推出来的信息。

⚠️ 奖杯节点**没有底圈**，所以小径的淡红虚线不再被圆盘挡住、会从杯身上下穿过。
实拍确认这反而更好读：奖杯实心部分盖住线，露出的只有杯耳两侧 ——
像"奖杯骑在路线上"，比"圆圈套图标"少一层套娃。

## 四、标题下移 + 放大（地图页与章节页**同一套数**）

| 量 | 改前 | 改后 |
|---|---|---|
| 标题中心距屏幕顶 | 72 设计px（与返回键**同行**） | **109**（自成一行，落在返回键下方） |
| 字号 / 行盒 | 15 / 21 | **19 / 26** |
| 底栏高 | 96 | **124** |
| 列表起点 | 127 | **155**（+28） |

109 不是拍脑袋：返回键下缘 = 56 + 32 = **88**，再留 8 的空隙，加半个 26 的行盒 → 109。
`TOPBAR_H = 56 + 32 + 8 + 26 + 2 = 124`，`LIST_TOP = 124 + 31 = 155`。

章节页用的是**居中**而非顶锚，所以它不需要额外偏移 ——
底栏长高 28 ⇒ 居中区域缩 28 ⇒ 列表中心**自动**下移 14（实测 `.chap-list` 163.8，改前 150.0）。

### 版式比对（`tools/layout-diff.py map`）

主表 20 项，**超容差 3 项**，全部是这次**有意**下移造成的 +27.5 设计px：
`.topbar` / `.map-info` / `.map-wrap`。

```
.node-row[0..7]  步距 设计 78.0 / 实现 78.0   ✔ 全绿
.node[0..7]      三列 x = 20.2 / 151.9 / 283.7 ✔ 全绿
```

**排布算法一行未动**（`colX(i % 3, W)` 原样），符合用户"先保留现行的三列轮转"。

```bash
bash tools/cocos-build.sh web-desktop debug

  unlock:2:3 wait:2500 d:0,-534 p:chap d:0,335 p:map wait:1400
```
