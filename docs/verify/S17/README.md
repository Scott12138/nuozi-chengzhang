## 一、三个问题的像素级定位（不靠肉眼）

三条都用"量图 + 量日志"定的位，不是看截图猜的：

| # | 用户原话 | 实测证据 | 根因 |
|---|---|---|---|
| ① | 拖动不像原来的格子 | 「革」纸面顶边 **y=565**，而它所在行的正常顶边 **y=518** ⇒ 牌停在 row1/row2 **正中**，上方露出棋盘底 | 显示位置 = 手指位置（跟手自由滑） |
| ② | 格子会歪掉 | 「木」上边缘线性拟合斜率 **0.095** ⇒ 倾角 **+5.45°**，正好落在 `DRAG_TILT_MAX=6` 内 | 原型那句 `rotate(±6°)` 被抄进了 Cocos 版 |
| ③ | 能拉出边界之外 | 「木」越出棋盘左边界约 **半张牌宽** | 越界橡皮筋 `RUBBER_MAX = 20` 设计px |

**三条的公共根因**：判定走 `clampSlide`（正确），但**显示**被改成"手指去哪儿牌去哪儿"，
两者解耦 ⇒ 位置、角度、边界三件事一起失守。原型 `onMove` 本来就是：

```js
const p = clampSlide(d, nx, ny);
tileXY(d.el, p.c*G.cell + G.gap/2, p.r*G.cell + G.gap/2, ...);   // 直接摆到 p 那一格
```

## 二、改法：显示与判定同源

`game-5-chaizi/assets/scripts/ui/GamePage.ts` —— `onMove`：

```ts
if (d.axis === 'h') d.node.setPosition(this.cellX(p.c), this.cellY(d.homeR), 0);
else                d.node.setPosition(this.cellX(d.homeC), this.cellY(p.r), 0);
d.node.angle = 0;   // ★ 有意偏离原型的一处
```

| 删除的东西 | 位置 | 为什么 |
|---|---|---|
| `DRAG_TILT_MAX = 6` | 常量段 | 倾斜在手机上就是"格子歪了" |
| `RUBBER_MAX = 20` | 常量段 | 不允许"超出范围还能多走一点" |
| `rubber(v, lo, hi)` | 私有方法 | 同上 |

**两条附带的结构性收益**（都不是"顺手"，是这次改动的直接后果）：

1. **出界不用单独处理**：`clampSlide` 内部已经把落点夹在 `range` 内
   （`Math.max(range.up, Math.min(range.down, r))`），而 `range` 只含空格
   ⇒ 显示位置取 `p` 就天然落在格心、天然在棋盘内。
2. **判定与显示完全同源**：判定用 `p`、显示也用 `p`，不会再有
   "看着落在这一格、算的却是那一格"。

**为什么不回到"跟手"**：真机 `touchmove` 有抖动，跟手会把抖动**如实画出来**；
整格吸附只在**跨格那一刻**动一次。手机上手感上吸附比跟手顺 —— 这也正是用户说的"丝滑"。

## 三、新增硬断言 `dragcell:`（不看图，逐格查）

### 3.1 可测入口

`onMove` 里新增一行 diag（键名被 `tools/web-smoke.mjs` 的 `parseDrag` 解析，改名必须同步）：

```
[Diag] DRAG 字=革 格=5,4 节点=(168,-224) 期望=(168,-224) 角度=0.00
```

**采样规则**（这里踩过坑，见第五节）：**跨格** *或* 节点位置比上次采样又多走半格。
整格吸附下两者等价 ⇒ 零额外输出；而"跟手自由滑"下才会把越界那一段如实记下来。

### 3.2 三条判据

| 判据 | 破 = 用户哪句话 |
|---|---|
| `节点 === 期望`（±1 取整误差） | ① 不像原来的格子 |
| `\|角度\| ≤ 0.01` | ② 格子会歪掉 |
| `\|节点\| ≤ 最外一格的中心`（x∈[−280,280] y∈[−336,336] @L1） | ③ 拉出边界之外 |

### 3.3 怎么拖

照 `[Diag] SUGGEST` 的轴与方向，**一路拖到画布边**（比棋盘边界更远）再松手 ——
专门撞"出界"那一条。终点留 8 设计px 余量，保证**指针始终不离开 canvas**
（离开后浏览器不再派 mousemove，拖动会半路断掉，会伪装成"牌不跟手"）。

### 4.2 负控（`negctl/`，**故意改坏**，证明判据不是摆设）

只跑正控，是分辨不出"真判据"和"结构上恒真的假判据"的。所以做了一次负控：
把 `onMove` 的显示位置临时改回旧实现（跟手自由滑 + `rotate(5.45°)`），重跑：

```
❌ 跨到格(4,3)时节点在(56,-100)，格心是(56,-112)  —— 牌没落在格心上（"不像原来的格子"）
❌ 跨到格(3,4)时角度=5.45°                       —— 牌被倾斜了（"格子会歪掉"）
❌ 跨到格(3,0)时节点在(-351,0)，超出棋盘范围 x∈[-280,280] ——（"能拉出边界之外"）
小结：通过 0 轮，失败 2 轮
```

★ **三条判据全部报红，逐条对应用户的三句原话。**

### 4.3 ★ 负控揪出的一条"空转判据"（留档，别再写回去）

判据 ③ 第一版写的是「**落点格** (r,c) 必须在 rows×cols 之内」，看着很对，其实
**永远不可能成立** —— `格=` 就是 `clampSlide` 的输出，它内部已经夹过 `range`。
负控里牌明明已经滑到画布边，那一行却**依然全绿**。
⇒ 改成判**节点位置**。**这就是必须做负控的全部理由。**
（同理，第五节那个取样竞态，也是靠"间歇性红"才暴露出来的。）

## 五、本轮修掉的 3 个工装 bug（都极具误导性，全部留档）

### 5.1 `dragcell:3` 被 `drag:` 抢先吃掉 → 静默降级成 `drag:8`

`parseAction` 里 `drag` 用的是**前缀**匹配，而 `dragcell` 也以 `drag` 开头。
后果：`dragcell:3` → `s.slice(4)` = `cell:3` → `Number('cell:3')` = NaN
→ 静默退化成默认的 `drag:8`。**退出码 0、屏上一片绿**，只因为末尾顺带打出了几行 DRAG，
看起来"像是测了"。
⇒ 改成 `s.startsWith('drag') && !s.startsWith('dragcell')`（同 `push`/`pushidx` 的写法）。

### 5.2 取样竞态：读到的 `SUGGEST` 可能是**上一盘**的

症状：**间歇性**报「整段拖动一条 DRAG 行都没打」，6 轮里挂 1 轮、复跑又全绿。

真因：`lastDiag(cdp, needle)` 是"**最后一条**含 needle 的行"，**不区分是哪一盘的**。
上一手消掉牌之后新盘的 `SUGGEST` 还没打出来就读它 ⇒ 拿到上一盘的走法；
照着它拖 = 按在一个**已经空掉**的格子上 ⇒ `onDown` 找不到牌 ⇒ 零 DRAG 行。

触发条件是 **宝牌成对**那一手：它是**链式延迟结算**的（本体 + 额外送掉一对），
实测**超过 700ms** 新的 `STATE/SUGGEST` 才落盘 ⇒ **任何按时间猜的等待都必然漏**。

**两个失败的修法（都留档）**：

| 版本 | 判据 | 为什么错 |
|---|---|---|
| v1 | "控制台行号 ≥ 某个 mark" | mark 记在取样**之前**，取样过程中才到达的那条也算"新行" → 下一轮立刻假通过 |
| v2 | "最后那条 `SUGGEST` 换成另一条" | 依赖"上一手改了盘面"这个前提，而**判断前提本身**又用了同一套不牢靠的时机 → 宝牌那手仍误判 |
| **v3（现行）** | **等"一整盘的 `STATE seq` 真的变大"** | 不看时间、不看行号，只看内容；慢到多晚都能等到 |

配套：新增 `lastDiagPass(cdp)` —— **整盘一起取**（BOARD/TILES/STATE/SUGGEST 同一次 dump）。
因为游戏一次 dump 的顺序固定（BOARD→TILES→STATE→SUGGEST→…）而 CDP 逐行送达，
分别取会拿到**两盘混起来**的数据，而混盘组合恰好能骗过所有"两边对比"型自洽检查。

★ 好性质：那手若**真的没改盘面**（严格回弹），等不到新盘时旧那一盘依然是对的
（盘面没变）⇒ 超时返回当前那一盘是安全的，不是将就。

### 5.3 `wechat-preview.sh` 的归档 README 把"合计"当成"主包"

原模板写成一行：`包体 | 7052703 字节（6.73 MB，红线 4MB）`。
**4MB 红线管的是主包**，而 7 MB 是主包+全部分包的合计 ⇒ 读起来像"超红线一倍"，
足以让人去砍本不需要砍的资源。实测主包只有 **3.16 MB（余量 861 KB）**。
⇒ 拆成两行，各带各的口径，主包那行直接给"是否在红线内"。
