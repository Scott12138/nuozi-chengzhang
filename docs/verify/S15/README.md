## 一、改了什么（三处，一条主线）

### 1. 新增 `core/Solver.ts` —— 规则与搜索的唯一内核

把原先只在 `tools/solve-exact.js` 里的搜索层整体搬进 `core/`：

| 导出 | 作用 |
|---|---|
| `firstHit` | 落位后**引擎口径**第一个被消掉的是谁（与 `matchTargets` 行优先序逐字一致） |
| `listActions` | 此刻玩家真能消掉的所有对 `[{t, o, x}]` |
| `settle` | 落实一步，并把「宝牌赠品送掉哪一对」记进动作 |
| `search` | DFS + 失败态记忆 + 节点/时间双上限 |
| `greedy` / `greedyAny` / `greedyPlan` | 换随机顺序贪心（便宜档） |
| `planFor` | 两段式强规划器（贪心 → 全败上 DFS） |
| `solvable` / `solvableInPlace` | 两段式判定；前者用工厂（离线），后者就地（运行期） |

**两条硬约束写进了文件头，任何改动不许破坏：**
- 零 `cc` 依赖（与 `core/` 全体同规矩，这样才能用 node 跑断言）；
- 判定函数返回时**盘面必须原样**（含撞预算的异常路径 —— 这条踩过两次，
  两次症状都被误读成「游戏规则有问题」）。

**一个刻意的实现选择：预算哨兵用字段，不用 `class extends Error`。**
微信小游戏的构建链有一档「ES6 转 ES5」，那里 `extends Error` 的 `instanceof`
会**静默失效** —— 撞预算会被当成崩溃抛出去，而不是被当成「没算完」。
这类 bug 只在真机上出现，本地 Node 跑得好好的。

### 2. `tools/solve-exact.js` —— 从 1007 行瘦到 702 行

删掉与 `Solver.ts` 重复的内核，改成一层**转发壳**（`S().xxx`）。
不是逐处改调用点（几十处，改一遍的风险大于收益），而是让「这里已不是真源」写在明处，
同时保持 `module.exports` 形状不变，调试脚本不用跟着改。
另外顺手删掉两个**从未被调用**的死函数（`hClear` / `vClear`）。

### 3. `GamePage.reshuffleRemaining()` —— 判据从「能动一下」升级到「整盘可解」

**旧判据**：`hasDirectMatch || findSuggest` ＝ **只保证"至少有一对能消"**。
玩家点「看广告重排」收到「盘面已重排」的正反馈，消掉那一对之后照样可能是死局，
于是又被弹回弹层、再看一次广告。**承诺是"能走"，兑现的是"能动一下"。**

**新判据**：调 `solvableInPlace`，与离线逐关判定**同一个函数**。

运行期给不起离线那样的算力，所以分档花（常量写在 `GamePage.ts` 顶部）：

| 档 | 预算 | 说明 |
|---|---|---|
| 便宜档 | 每轮 8 次贪心（约 6ms） | **每轮都做**；一次贪心实测 ~0.7ms、单次命中率 25~35% |
| 贵档 | DFS 600ms / 20000 节点，**整轮共享** | 只有便宜档全败、且窗口未过才上 |

三个结果的处理：

| 判定 | 含义 | 动作 |
|---|---|---|
| `YES` | 拿到完整走法 / DFS 证明了有解 | 用这个盘面 |
| `NO` | DFS 穷尽 —— **唯一的"真的走不动"证据** | 换下一个顺序 |
| `UNKNOWN` | 只跑了便宜档，或 DFS 撞预算 | **不当作无解**，先记下这个盘面，继续换顺序 |

30 个顺序都没 `YES` 时**回退到第一个 `UNKNOWN` 的盘面**并放行 ——
「没能证明可解」不等于「走不动」，而盘面**已经被重排过了**；
把玩家丢回弹层逼他再看一次广告，比放行更糟。
只有 30 个顺序**全被 DFS 穷尽证伪**才返回 false。

## 二、验证证据

### ① 内核语义零回归（最关键的一条）

`--mode levels --levels 1-38 --seeds 8 --bonus none` 全量对账，**改前 vs 改后逐字一致**：

| 指标 | 改前 | 改后 |
|---|---|---|
| 有解 | 257 | **257** |
| 真无解 | 41 | **41** |
| 未知 | 6 | **6** |
| 贪心命中 / DFS 命中 | 241 / 16 | **241 / 16** |

归档：`solve-none.json`（`--board-time 15000`，`docs/verify/S15/`）

**只有一处 4 秒预算下的回放差异**（L36 某盘、L34 某盘），复跑三次后归零 ——
是时序抖动（同一盘在 4s 边缘有时算完、有时算不完），不是逻辑回归。
这件事本身恰好印证了 `UNKNOWN` 这个三态的必要性。

### ② 顺带修掉一个工具 bug：`--board-time` 对回放不生效

`playReal` 的调用处传的是 `deadline: Date.now() + opt.boardTime`，
而 `playReal` 读的是 `opt.boardTime` ⇒ 永远 `undefined` ⇒ 落到 `boardMs || 4000` 兜底值。
**后果**：`--board-time` 只管判定层，回放恒为 4 秒，而文档写着它管回放 ——
于是「回放没算完」会被误读成「这盘走死了」。

修复后的决定性对照（同一盘面，只换回放预算）：

```
boardTime=    1ms → cleared=false 步数= 0  原因=规划没算完（DFS 撞预算）
boardTime=20000ms → cleared=true  步数=34  原因=（通关）
```

修复后对账档：**223/223 = 100%**（此前 221/223，2 条是"没算完"）。

### ③ 自检

  新增的四组：
  - **动作集与引擎逐字对账**：`listActions` vs 手写"暴力枚举 matchTargets[0]"
  - **契约**：`solvableInPlace` / `greedyPlan` / `search` 返回后指纹不变（含撞预算路径）

### ④ 运行期开销实测（新增判据会不会卡）

逐字复刻 `GamePage` 那段逻辑（30 轮 / 8 次贪心 / 600ms & 20000 节点窗口），
在**真能走到的中局盘面**上量（先跑一条完整方案、执行掉前 50%/75%）：

```
样本 78 次 · 中位 1 ms · p90 3 ms · p99 61 ms · 最慢 61 ms
最慢那一次：L34 剩34张 → YES/greedy@3轮
```

**78 次里 DFS 只走了 1 次** —— 便宜档足够强，判据升级几乎不花钱。

### ⑤ 冒烟：死局 → 重排链路（debug 构建）

```
[GamePage] L3 开局就绪：32 张牌 … 种子=force:403464159
[GamePage] 卡住：无可立即凑成的挪法 → 弹「看广告重排」
[AdGate] 弹出：卡住了 / 看广告重排
[Diag] SUGGEST none    [Diag] REACH direct=0 suggest=0 → 真的卡住
[GamePage] 请求激励视频（看广告重排）
[AdService] 未接入激励视频 → 直接发放
[GamePage] 重排第 1 轮 → 可解（greedy，14 手）      ← ★ 新判据生效
[GamePage] 看广告重排 → 有解
[Toast] 盘面已重排
```

**这一屏就是两个判据的区别**：死局检测说"一步都走不了"（它该问的正是这个），
重排判据说"整盘 14 手能通关"（它该问的是这个）。
旧判据在这里会返回什么？—— 它只查"至少有一对能消"，重排出来的盘面**可能**满足，
但没有任何证据说明"整盘能通关"。这正是本轮要堵的洞。

⚠️ 死局检测（`checkDeadlock`）**故意不改**：它问的是"现在还有没有一步能走"，
不是"整盘能不能通关" —— 两者是不同的问句，判据本来就该不同。

## 三、口径声明（供复查）

- 判定层口径固定 `bonus: 'none'`（不发宝牌赠品）—— 回答"**这张牌面本身是不是死局**"。
  赠品是随机的，"存在一条运气好的路线"不是玩家能指望的东西。
- 真机口径（赠品现抽）另算：`--bonus real`。两个数字一起看才有意义。
- 本工具给的是**「存在通关路径」（∃）**，不是"无论赠品送哪一对都通关"（∀）。
