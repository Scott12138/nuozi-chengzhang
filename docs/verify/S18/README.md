## 一、第 1 条：提示不再挡棋盘

截图里被红圈圈住的是 `tapTile` 弹出的**两行**提示（「它和「竹」能拼成字／但要先挪到
同一行或同一列」），它挂在屏幕 **52%** 高度上 —— 那正好是棋盘中部，两行能盖掉一整行牌。

| 改动 | 文件 | 说明 |
|---|---|---|
| 提示条改成**按上沿**定位 | `ui/Toast.ts` | 构造参数 `centerY` → `topEdgeY`；`redraw` 末尾补 `setPos(0, topEdgeY − h/2)` |
| 落点锚在**棋盘下沿之下** | `ui/GamePage.ts` `buildOverlays` | `Math.min(belowBoard, bandTop)`，`belowBoard = boardCy − boardH/2 − px(10)` |
| **删掉**两行长提示 | `ui/GamePage.ts` `tapTile` | 指路改由**牌面闪烁**承担（见 §三） |

**为什么"按上沿"而不是"把中心往上挪"**：两行提示的高度是单行的 1.5 倍。
按中心定位时高度一变，**下边不动、上边往上长** —— 越长的提示越会顶到牌上。
改成按上沿定位后，行数一多只会**往下长**，永远不会反向上侵棋盘。

## 二、第 2 条：开局密铺 + 保底相邻可消对

### 2.1 破局的关键：铺满 ⇒ 一张牌也滑不动

铺满之后棋盘上**没有空格**，而滑动的落点**只能是空格**（`slideRange` 只含空格）。
所以"铺满的开局"如果什么都不做，就是一个**死局**：玩家第一步无处可走。

用户原话的后半句「**而且开局时要有一些相邻可以直接消除的**」正好是出路 ——
开局唯一能走的一步，是「两张**已经挨在一起**且能配对的牌点一下消掉」。

⇒ 新增 `OPEN_PAIRS = 2`（`core/Board.ts`）：「一些」的最小诚实实现，想调开局难度改这一个常量。

### 2.2 发牌内核重写（确定性、无重试、无递归）

旧版是「撒完 → `hasDirectMatch` 不成立就整体重撒，最多 24 次，且只对 `n ≤ 3` 生效」。
新版 `generateBoard`：

1. 先从牌堆里挑 `OPEN_PAIRS` 组"能配对的两张"（第一轮要求每组是**不同字**，凑不满再放宽）；
2. `anchorCells` 给它们分配**横向相邻两格**的落点（两对彼此至少隔一格，否则会共用一张牌）；
3. 保底对先占住自己的两格，其余牌按**行优先**补满剩余格子。

**全程只做置换**（用的仍是同一副牌堆，不增减任何一张牌），所以：
一次成功、没有重试预算、对全部 38 关一律生效、且仍然可复现。

### 2.3 ⚠️ 做不到「100% 零空格」（与字频三条的数学冲突）

这是本轮**必须回报**的一处：字面要求与既有规则冲突，我按"最接近字面"实现。

| 事实 | 来源 | 后果 |
|---|---|---|
| 牌数恒为偶数 | `buildDeck` 每次成对 push（偏旁+部件 / 宝牌×2） | 格子是奇数时永远差一格 |
| 关卡表格数为**奇数**的有 **7 关** | `core/LevelData.ts` 实测 | 这些关按关卡表永远铺不满 |
| 实际棋盘行数 = `ceil(牌数 / cols)` | 本轮改法 | 棋盘边框收紧，**末行可能不满** |
| 每关的**对数**被「字频三条」封顶（一种组合 ≤2 组 / 相同偏旁 ≤4 张，今日早先拍板） | `pairs` 相对 `words` 的取值 | 「靠加牌把关卡表填满」这条路是堵死的 —— 想填满 6×6 就要 18 对，而 L1 只有 7 个词 |
| 38 关"密铺后仍空出的格"合计 **125**、单关最多 **7** | 实测（见下表） | 平均每关 3.3 格 |

| 关卡 | 词数 | pairs | 牌数 | 关卡表 | 密铺后实际棋盘 | 仍空出 |
|---|---|---|---|---|---|---|
| L1 | 7 | 14 | 28 | 6×6 (36) | 6×5 | 2 |
| L4 | 8 | 15 | 32 | 6×7 (42) | 6×6 | 4 |
| L8 | 10 | 19 | 40 | 7×8 (56) | 7×6 | 2 |
| L14 | 12 | 24 | 52 | 9×9 (81) | 9×6 | 2 |
| L23 | 14 | 28 | 60 | 10×10 (100) | 10×6 | 0 |
| L34 | 16 | 31 | 68 | 10×12 (120) | 10×7 | 2 |

> 关卡表里那几十个空格的**容量**现在全部作废：`lv.cols/lv.rows` 降格为"容量上限"。
> 视觉上棋盘会随牌数**收紧**（不再是一块大黑板里稀稀拉拉几排牌）。

### 2.4 关键推论：所有几何都要跟着"实际棋盘"走

密铺后实际行数 < 关卡表行数（L14：9×9 → 9×6；L34：10×12 → 10×7）。
如果几何继续用 `lv.rows` 去居中，**整盘会歪在棋盘上方**（不报错、不看图发现不了）。

| 位置 | 改动 |
|---|---|
| 新增字段 `_cols` / `_rows` | `onCreate` 设完板后 `= board.cols / board.rows` |
| `computeGeometry` | `cols/rows` 取 `_cols/_rows`；`boardH = px(rows * pitchD)` |
| `cellX` / `cellY` | 同上 |
| `[Diag] BOARD` + 开局日志 | 打 `cols=/rows=`，并注明"关卡表 N×M，密铺后行数收紧" |

## 三、第 3 条：多选配对的呼吸闪烁

**判据**：某张牌**四方向紧邻**的、能与它配对的搭档 **≥ 2** ⇒ 它和这些搭档一起呼吸。

- 用「紧邻」而不是 `lineClear`：用户原话就是「左/右/上/下」；
  且**紧邻必然满足 `lineClear`** ⇒ 一定能点得掉，不会出现"闪了却消不掉"。
- **只有一个搭档时不闪**：没有"选择"可言，闪了反而把注意力从唯一那一步引开。
- 用**呼吸**（`FLASH_HI 1 → FLASH_LO 0.22`，8 步 ×160ms）而不是常亮：
  拖动中的金圈是**结果预览**，这个是**待选**，两者观感必须一眼分开。

**它挂在 8 个盘面变化点上**（漏任何一个都不会报错，只是"那个场景下不闪了"）：

| 调用点 | 动作 |
|---|---|
| `onCreate` 就绪段（紧跟 `diag('开局')` 之后） | `refreshFlash()` |
| `onMove`（位移首次超过 `DRAG_SLOP` 那一刻） | `clearFlash()` |
| `applyMove` 的 130ms 回调（走"挪牌"分支） | `refreshFlash()` |
| `resolveMatch` 入口 / `MATCH_CLEANUP_MS` 清理回调 | `clearFlash()` / `refreshFlash()` |
| `resolveTreasure` 入口 / 清理回调 | 同上 |
| `reshuffleRemaining` 的收尾 `settle()` | `diag('洗牌')` + `refreshFlash()` |
| `onUp` 的"拖回原格"与"严格回弹"两条路 | `refreshFlash()`（盘面没变，原样还回去） |
| `finishClear` / `finishFail` / `onReviveAd` | `clearFlash()` … `refreshFlash()`（复活后重新算） |

**为什么"收掉"放在 `onMove` 而不是 `onDown`**：`onDown` 分不清"玩家要点"还是"玩家要拖"。
在那里就收的话，**单纯点一下**也会让闪烁消失，而 `tapTile` 的"点到了但没能消"那条路
**不会**重算它（提示文案已删、指路全靠闪烁）⇒ 闪烁会一直黑着，直到下一次盘面变化。

## 四、第 4 条：四个道具

顺序 = 工具栏从左到右 = `ToolKey = 'hint' | 'bomb' | 'shuffle' | 'time'`：

| 位置 | 标签 | 次数 | 行为 |
|---|---|---|---|
| 1 | 提示 | 3 | 已有（优先指"已对齐、点一下就能消"的那对） |
| 2 | **消除** | 1 | 原「凑对」改名；**无视滑动限制**直接成一次字（唯一改规则的道具，所以只给 1 次） |
| 3 | 洗牌 | 1 | 已有（整盘重排 + 可解性判定） |
| 4 | **延长时间** | 1 | **在现有倒计时上加 30 秒**（`CFG.GAME.REVIVE_SEC`），走"加秒"而不是"重置" |

- `TOOL_COUNT = 4` 收成常量（它同时被 `buildTools` 排版与 `dumpLayout` 版式 dump 消费）。
- **字段名 `BOMB` 保持不变**（只改玩家看得到的标签）：改名的收益只是好看，
  代价是牵动存档 / 工装 / 日志三处。
- 「延长时间」的坑：加完**必须把表重新挂上** —— `_tickId` 已停时要 `startTimer(left + add)`。
  只改 `_deadline` 而不重挂的表现是"点了没反应"，且不报任何错。

### 顺手修掉的一个静默坏法（本轮实测踩到）

`dumpLayout` 里 `toolW` 已经改成 `/ TOOL_COUNT`，**循环上界却还写死 3** ——
于是版式 dump 里只有前三个道具框，第四格（延长时间）的版式验证被悄悄抹掉。
已改成 `i < TOOL_COUNT`，现在 dump 里 `.tool[0..3]` 四个框齐全。
