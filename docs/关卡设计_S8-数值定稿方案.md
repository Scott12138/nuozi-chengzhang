## 一、★ 几何硬约束：12×12 必须放宽 `CELL_MIN`

### 1.1 机制

棋盘格宽**按可用区域反算**（`GamePage.computeGeometry()`，逐条照搬原型 `computeCell`）：

```
cell = min( floor((可用宽 − 4) / 列数), floor((可用高 − 4) / 行数) )
cell = clamp(cell, CELL_MIN, CELL_MAX)      ← 最后一步兜底（现状 32 / 62）
gap  = max(3, round(cell × 0.09))
```

实测锚点（L1，含 tips，最保守）：**可用宽 352 设计px、可用高 476 设计px**。

### 1.2 逐尺寸实测

| 棋盘 | 格数 | 理论格宽 | CELL_MIN=32 时 | CELL_MIN=29 时 | 结论 |
|---|---|---|---|---|---|
| 8×8 | 64 | 43 | 43（宽 344） | — | ✅ |
| 10×10 | 100 | 34 | 34（宽 340） | — | ✅ |
| 11×11 | 121 | 31 | 32（宽 352，刚好贴满） | — | ✅ |
| 11×12 | 132 | 31 | 32（宽 352） | — | ✅ |
| **12×12** | **144** | **29** | **32 → 宽 384 ❌ 溢出 32** | **29 → 宽 348 ✅** | 需放宽 |

**根因**：`CELL_MIN=32` 把 12 列的 29 抬到 32 → `12 × 32 = 384 > 352`，左右各出屏 16 设计px。
**列数是唯一瓶颈**：高度方向富余很大（12 行 = 384 ≤ 476）。

**落地动作**：`CFG.BOARDGEO.CELL_MIN` 由 `32` → **`29`**（一次性常量改动，其余算式不用动）。

### 1.3 字号代价（用户拍板：等比例缩小即可）

牌面是**烘死的 192×192 位图**（`assets/resources/tiles/*.png`），缩放比例直接决定字号 —— 无法"只缩格子不缩字"，只能整体等比缩。

| 关卡 | 格宽 | 牌面(设计px) | 牌面(物理px) | 汉字估算 | 可读性 |
|---|---|---|---|---|---|
| 现状 L1（6×5） | 58 | 53 | 103 | ≈ 25 pt | 很清楚 |
| 新版 6×6 | 58 | 53 | 103 | ≈ 25 pt | 很清楚 |
| 新版 8×8 | 43 | 39 | 75 | ≈ 18 pt | 清楚 |
| 新版 10×10 | 34 | 31 | 60 | ≈ 14 pt | 可读 |
| **新版 12×12** | **29** | **26** | **50** | **≈ 12.6 pt** | 偏小但可读 |

> 口径：物理px = 设计px × 1.9355；pt = 物理px ÷ 3（3x 屏）；汉字 ≈ 牌面 × 0.75。

## 三、宝牌规则

| 项 | 值 |
|---|---|
| 登场关 | **L7（7×8，56 格）** |
| 分界 | 格数 < 56 → **0 对**；56~72 → **1 对**；81~110 → **2 对**；≥121 → **3 对** |
| 上限 | **3 对** |
| 机制 | 两张**同款**宝牌像普通牌一样挪到同行/同列且中间无挡 → 触发奖励：**随机消掉盘面上一对可合成的牌**，宝牌自身同时消失 |
| 与干扰牌 | **宝牌取代干扰牌** —— 现有 `junk` 机制整体下线 |

**对操作次数的影响（重要，别当成"白送难度"）**：设普通对 `pairs` 组、宝牌 `tr` 组

- 盘面牌数 = `2×pairs + 2×tr`
- 玩家实际出手 = 消掉 `(pairs − tr)` 组普通对 + `tr` 组宝牌 = **`pairs` 次**

即宝牌对总操作次数是**中性**的（每凑一对宝牌，替玩家省掉一对普通对）；它的价值在**视觉减负 + 节奏爽点**，不在数值减负。

## 四、对数与空置率

占用格数取**等差 +4/档**（13 档 → `28, 32, …, 76`），由此：

- **可消对** `pairs` = `占格/2 − 宝牌对数`
- **空置率** 从 **22.2%**（6×6）单调升到 **47.2%**（12×12）

**为什么空置率必须随盘面变大而升高**：这是本玩法的物理前提。
现状 L38 只剩 **6.1% 空格（3 格）**，这正是历史实测「L7、L37 三次采样全无解」的根因 —— 盘面塞满后每张牌四向全堵，一步都动不了。
新版锁在 22%~47%，**「开局确定有解」才有物理基础**。

## 五、限时模型

### 5.1 市面参考（已查证）

| 游戏 | 尺寸 → 限时 | 每对预算 |
|---|---|---|
| 免费宠物连连看 | 6×6/120s → 8×8/90s → 10×10/60s → 12×12/45s | 随盘面**递减** |
| 加一连连看 | 6×6/60s → 8×8/90s → 14×8/120s → 14×10/150s | — |
| 中秋连连看（教程） | 8×8/240s → 10×10/180s → 12×12/120s | — |
| 猫咪连连看 | 4×4/60s → 6×6/90s → 8×8/120s → 20对/150s → 24对/180s | **恒定 7.5 s/对** |

**关键差异**：市面全是**点选式**（点两张同图即消，单对 1~2s），大盘反而给更短时间。
**本作是拖动合成式**（找 → 判对齐 → 拖 → 落，单对 5~9.5s），**时间必须随盘面递增**，不能照抄市面曲线。

### 5.2 模型（已按拍板定稿）

```
T = (可消对 pairs × 9.5s  +  格数 cells × 0.2s)  ×  章首系数  +  冗余
章首系数：L1 = 1.25（教学）　其他章首 = 1.10　其余 = 1.00
冗余     = 60s × (cells − 36) / 108      // 6×6 = 0s，12×12 = 60s（"多给 1 分钟冗余"）
```

- `9.5 s/对`：拍板值（现状章末每对约 5.7s、玩家反馈偏紧 → 放宽约 67%）。
- `cells × 0.2s`：盘面**扫视附加**（找牌成本随盘面增大）。
- `冗余`：直接落实"市面单局可到 12 分钟，不必局限，多给 1 分钟冗余"。

### 5.3 结果对照现状

| 关 | 现状 | 新版 | 放宽 |
|---|---|---|---|
| L1 | 150s | **175s** | +17% |
| L8（章1末） | 122s | **205s** | +68% |
| L16（章2末） | 122s | **270s** | +121% |
| L28（章3末） | 120s | **365s** | +204% |
| **L38（终章）** | **120s** | **420s（7 分）** | **+250%** |

单局上限 **7 分钟**，在市面参照（最高 12 分钟）之内 ✅

## 七、复现

```js
CELLS = [36,42,49,56,64,72,81,90,100,110,121,132,144]
used  = 28 + 4 * indexOf(cells)
tr    = cells < 56 ? 0 : cells <= 72 ? 1 : cells <= 110 ? 2 : 3
pairs = used/2 - tr
time  = round( ((pairs*9.5 + cells*0.2) * bonus + 60*(cells-36)/108) / 5 ) * 5
```

几何复现：`CFG.BOARDGEO` + `GamePage.computeGeometry()`；实测锚点 `availW=352 / availH=476`。

> ⚠️ 与 `关卡设计_S8-棋盘节奏方案对比.md`（上版）的关系：上版最大尺寸是 **8×8**，本版按新拍板把终点推到 **12×12**，
> 并**替换**了节奏、宝牌、限时三张表。上版的 A/B/C 三版节奏对比仅作历史留存。
