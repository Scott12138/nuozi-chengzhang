### 提示词基线（可复现）

```text
用途：微信小游戏《挪字成章》关卡地图页里「锁住 / 未开放」的关卡节点角标，
      最终会被缩到约 58 设计px 显示，压在圆形的关卡节点上。
要点：Q 版卡通风（不是写实）；金色圆润挂锁，锁体短胖、无尖角；
      链条要**成对**垂在两侧、链环粗而少（细碎链条缩到 58px 后会糊成一团）；
      正面略偏斜、带一个高光；轮廓要深色粗描边，小尺寸下仍能一眼认出是「锁」。
用途约束：画面里**不要任何文字、数字、logo、品牌文案、水印**；
          纯色浅底、主体居中、四周留白（方便抠图）。
```

| 版本 | 观感 | 结论 |

| v1 | 偏写实、链条细碎 | ❌ 未采用 —— 缩到 58 设计px 后认不出是锁 |

### 处理链路

```bash
# 1) 出图（浅色底 —— ImageGen 的 transparent 参数常失效，别指望它直接给透明底）
#    → images/generated/lock-v1|v2/用途_…_<时间戳>.png

# 2) 抠透明底（浅色底 flood-fill）+ 缩到最长边 256 + 量化到 160 色
/Users/consli/.workbuddy/binaries/python/envs/default/bin/python \
  /Users/consli/.workbuddy/skills/cute-cartoon-assets/scripts/process_assets.py …

# 3) 入库（★ meta 的 userData.type 必须是 sprite-frame，否则引擎当普通贴图，Sprite 取不到帧）
cp <处理后>.png game-5-chaizi/assets/resources/ui/lock.png
```

量化参数：`quantize(colors=160, method=FASTOCTREE)` —— 把 540 KB 的原图压到 36 KB，
同时保住描边与高光的层次。

### 使用位置（代码）

* `game-5-chaizi/assets/scripts/ui/MapPage.ts`
  * `LOCK_TEX = 'ui/lock'` —— `mkSprite` 收**完整相对路径**，不补前缀
    （`tiles/` 那个前缀是 `texNameOf` 自己拼的，两套别搞混）
  * `LOCK_W = px(58)` —— 实际显示 58 设计px，宽高比 `241/256` 由代码算
  * 两个透明度档（设计稿原本只有 `.node.locked{opacity:.4}`，那是给"灰圆+序号"用的，
    换成真实锁图后按背景重标定）：`LOCK_A_UNLOCKED = 209`（已解锁但尚不可玩）、
    `LOCK_A_UNPLAYABLE = 128`（未开放）

### ⚠️ 抠图脚本被这批素材打出的一个真 bug（已修）

`process_assets.py` 原来的容差自适应只试 `(26, 16)` 两档，判据是「前景占比 ≥ 10%」。

**对"靠明暗层次表现纵深"的素材不成立**：AI 生成的"纯白底"上，主体与背景之间是
**抗锯齿的平滑渐变**，BFS 会顺着渐变**一路爬进主体**（每单步色差都小于容差）。
主体里越浅的部分越先被吞 —— 远山、薄雾、奶白机身、浅色花纹。

实例：`mount-B`「三峰叠影」里两座浅灰蓝（#9AA6AF）远山被整片吃掉，只剩最前面那座
深色近山，输出变成一个"平顶墨块"。**自检表完全看不出来**（主体岛 1、空洞 948px，
每一项都是"正常"）。

已改成「**占比收敛判据**」：从大到小扫 8 档容差，取**第一次达到平台**的那一档
（= 背景够干净、又还没开始抠穿）。修完 `mount-B` 自动落到 `tol=11`，
空洞 948px → 14px，体积 18KB → 29KB（主体补齐）。

扫描数据留档（可复现）：

```text
mount-B   tol 扫描  26:0%  20:0%  16:15%  13:20%  11:24%  9:24%  7:24%  5:24%   → 选 11
trophy-A  tol 扫描  26:25% 20:25% 16:25% ... 5:25%                              → 选 26
```

脚本已留档：`tools/process_assets.py`（与技能内 `scripts/process_assets.py` 同源）。
